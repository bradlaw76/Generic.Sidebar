Agent Productivity Pane (Generic Sidebar)

⚠ This solution is provided for demo purposes only. Use at your own risk.

This kit renders a configurable side pane in model-driven apps. It reads one row from Generic Sidebar (sidebar_genericsidebar) where Default = Yes, then displays Instructions and an Embed (Copilot, Web Resource, Power Apps Canvas App, or URL). No code changes are needed to swap content—just flip the Default row.

How It Works

Form OnLoad / Ribbon→ Query Default Row→ Open Side Pane→ Render Instructions + Embed

Quick Start

  1. Create (or ensure) exactly one row in sidebar_genericsidebar with sidebar_default = Yes.
  2. Set:
    • sidebar_title — pane header title.
    • sidebar_instructions — rich text band (bullets/headings supported).
    • sidebar_embedcode — either a URL, webresource:Name.html, a full <iframe> snippet, or a Canvas App embed.
  3. Add the JS web resource to your form and set On Load handler → Generic_OpenSidebar.
  4. Publish all customizations. Hard refresh (Ctrl+Shift+R).

Troubleshooting

  • “Method does not exist” → Ensure Generic_OpenSidebar is published and attached.
  • Blank pane → Ensure one row has sidebar_default = Yes.
  • Odd bullets → Rich Text field normalizes them.
  • External site blocked → Host may disallow iframe (X-Frame-Options).
  • Chat resets on tab switch → Upgrade to sidebar v2.6.0+ (iframes now hidden, not destroyed).
  • Chat resets when OOB pane opens → Use the pop-out button (↗) to keep chat in separate window.

Pop-out Window (v2.11.0)

When Dynamics 365 opens an OOB sidecar (Smart Assist, Copilot Studio), the custom sidebar is unloaded. Use the pop-out button (↗) to open your Copilot chat in a separate window.

  • Bring to Front — Focus the pop-out window from the sidebar placeholder.
  • Restore Here — Close pop-out and reload content in sidebar (resets chat).
  • Auto-restore — If you close the pop-out window, the sidebar restores automatically.
Tip: Position the pop-out window on the right edge of your screen for easy split-screen snapping (Win+Arrow keys).

Install and administer Generic Sidebar

This guide replaces the short welcome page with the complete installation process. The sidebar is table-driven: administrators configure its panels in Dataverse; most content changes do not require a web-resource deployment.

Before changing production: capture the current Git commit, solution version, default configuration row, and a browser screenshot for rollback evidence.

Prerequisites

  • System Administrator or System Customizer access in the target environment.
  • Access to the Generic Sidebar solution and the model-driven form to be wired.
  • Read access to sidebar_genericsidebar and active sidebar_genericsidebaragent rows.
  • For SSO: Copilot Studio access, Entra app-registration permissions, and tenant approval.

1. Deploy web resources

  1. Open the target environment and select the unmanaged Generic Sidebar solution.
  2. Update the approved HTML and JavaScript web resources from source control; do not rename a resource without updating its references.
  3. Publish the changed resources. If targeted publishing is blocked by a concurrent customization, use a controlled full publish.
  4. Hard refresh the model-driven app with Ctrl+Shift+R before testing.

2. Configure Dataverse

  1. Create or select a sidebar_genericsidebar row.
  2. Set exactly one intended row to sidebar_default = Yes. Fix duplicate defaults rather than relying on the latest-modified safeguard.
  3. Set titles, instructions, and embed values for each panel. Supported values include a permitted URL, webresource:resource_name, an iframe snippet, or raw HTML.
  4. Set sidebar_agentmenutab only when the linked-agent picker should occupy a configured tab.

3. Wire the model-driven app

  1. Add sidebar_sidebar.js as a form library.
  2. Configure the approved sidebar entry function on Form OnLoad or the required ribbon command.
  3. Save and publish the form.
  4. Open a record and confirm the pane renders the intended default configuration.

4. Configure linked agents

  1. Create child rows in sidebar_genericsidebaragent and link them to the parent configuration.
  2. Set sidebar_isactive = Yes and keep each row in active Dataverse state.
  3. Confirm only active agents appear in the picker; disabled or deactivated rows must remain hidden.

5. Enable Copilot SSO (optional)

  1. Deploy sidebar_sso_bootstrap.js, sidebar_sso_setup.js, sidebar_sso_canvas.html, and sidebar_sso_config_validator.html.
  2. Register the canvas web-resource URL as a SPA redirect URI in Entra ID.
  3. Populate client ID, tenant ID, scope, token endpoint, redirect URI, and any additional scopes in Dataverse.
  4. Run the validator, then test SSO only in the hosted model-driven application.
Security: Do not put a client secret in browser-facing Dataverse configuration. Browser SSO uses PKCE.

6. Validate before release

  • One expected default configuration is active.
  • Every configured panel loads, including its instruction band.
  • Active linked agents appear and inactive agents do not.
  • Non-SSO scenarios work before enabling SSO.
  • SSO popup and silent sign-in work without placing tokens in logs or tickets.
