Copilot Chat Host — Standalone Preview

Not connected to your existing sidebar or solution.

Configure a test agent, then select Start chat.

Configuration and setup instructions

This is an isolated prototype. Do not change today's demo configuration. No network connection to an agent starts until you select Start chat.

Deployment later, in a test environment

  1. Host this HTML, sidebar_CopilotChatHost.js, and sidebar_CopilotAuthRedirect.html on the same HTTPS origin. In Dynamics these would be three separate web resources. No existing resource, solution package, or Dataverse record is changed by these files.
  2. Copy the published agent's token endpoint from its compatible channel configuration. It must return JSON containing a short-lived token. Supply the correct Direct Line directLineDomain for that cloud, ending in /v3/directline. Do not paste a hosted webchat URL, Direct Line secret, or identity token. A secured channel may require a separately operated token broker; this preview does not implement one.
  3. For an anonymous agent omit auth. For an authenticated agent, configure supported custom-website authentication and SSO in Copilot Studio. Configure an Entra SPA/public-client registration, delegated consent, preauthorization as appropriate, and the agent's token-exchange resource.
  4. Add auth with clientId, authority, redirectUri, scopes, and tokenExchangeResourceUri. Register the exact deployed blank redirect page as an SPA redirect URI. Use the matching cloud authority and exact resource URI advertised by that agent's OAuth card. Optional loginHint can help silent SSO; it is not proof of identity.
  5. Optionally copy sidebar_CopilotChatHost.config.example.json to a deployment-owned JSON file and use ?config=relative-file.json. Only same-origin configuration is accepted. Configuration is public, remains editable, and never enables automatic startup.

Authenticated configuration shape (replace every placeholder; these are not working values):

{
  "tokenEndpoint": "https://YOUR-AGENT-TOKEN-ENDPOINT",
  "directLineDomain": "https://YOUR-DIRECT-LINE-HOST/v3/directline",
  "auth": {
    "clientId": "YOUR-SPA-APPLICATION-GUID",
    "authority": "https://YOUR-ENTRA-CLOUD-HOST/YOUR-TENANT",
    "redirectUri": "https://YOUR-HOST/PATH/sidebar_CopilotAuthRedirect.html",
    "scopes": ["YOUR-AGENT-DELEGATED-SCOPE"],
    "tokenExchangeResourceUri": "YOUR-EXACT-AGENT-EXCHANGE-RESOURCE-URI"
  }
}

Separate deployments/panels can use separate configuration files without modifying this component. The agent—not a sidebar switch—requests authentication. Authentication configuration alone does not trigger sign-in.

Browser and cloud requirements

Web Chat 4.19.1 and MSAL Browser 4.30.0 are pinned, integrity-checked browser bundles served from jsDelivr. MSAL loads only after an eligible agent OAuth card. Your CSP/network policy must permit those libraries and the configured agent, Direct Line, WebSocket, and Entra endpoints. Review SDK/CDN availability and compliance separately for commercial, GCC, GCC High, DoD, or other clouds. This preview supports Entra authorities in commercial, US government, and China clouds, but does not claim every channel/cloud combination is supported.

Silent SSO can be prevented by cookie policies, missing consent, or account ambiguity. The Sign in button opens a user-initiated popup for required login, consent, or MFA. The fallback displays the agent's original sign-in card; failure never changes the agent to anonymous mode. Pop-out creates a new conversation; it does not transfer the existing conversation.

Validation before integration

  • Anonymous agent: chat works, no MSAL load or user-authentication prompt.
  • Authenticated agent: matching Microsoft session exchanges silently where supported; test absent session, multiple accounts, consent, and MFA.
  • Test popup/cookie blocking, rejected token exchange, expiry, and wrong resource configuration. Confirm the original sign-in card remains available.
  • Test two differently configured hosts and later sidebar tab/pop-out behavior.
  • Validate in your own tenant. Mock tests are not a live SSO certification.
